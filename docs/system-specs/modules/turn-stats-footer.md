# Per-Turn Stats Footer (Elapsed Time + Credits)

## Overview

The dashboard persists per-turn measurement metadata on an assistant message and renders it as a muted footer when that message is the completed turn's final assistant message. `_attach_turn_stats` (`dashboard/chat_turn/turn_stats.py`, called through `chat_runner`) keeps the metadata on the message before persistence, so the `chat_done` refresh can restore the same footer after reconnects.

## Data flow

```
ACP metadata / provider usage
        │
        ▼
TurnUsage on EVENT_COMPLETE
        │
        ▼
chat_runner captures elapsed, credits, cost, and model
        │
        ▼
_attach_turn_stats(slot, ...) → meta["turn_stats"] on a current-turn assistant message
        │
        ▼
chat_done → refreshSlot → persisted metadata
        │
        ▼
AssistantMessage renders the footer when its presentation gates permit it
```

## Backend (`src/kiro_crew/dashboard/chat_runner.py`, `chat_turn/turn_stats.py`)

`_run_chat` captures a monotonic start time and message boundary at turn start. On `EVENT_COMPLETE`, `_on_complete` (`chat_turn/turn_stats.py`) prefers `TurnUsage.duration_ms` when present and otherwise measures elapsed time locally; it reads credits and cost from `TurnUsage` and calls `read_turn_model(client)` for the usage record and `read_reported_turn_model(client)` for the footer, which names the model the harness reported running. ACP credit telemetry is accumulated from `meteringUsage` entries whose unit is `credit` by `acp.client_usage._track_metadata`; `acp._dispatch.parse_metadata` applies the same unit filter for the shared dispatch path.

`_attach_turn_stats(slot, elapsed_ms, credits, cost_usd, turn_boundary, model, ttft_ms, turn_start_mid)`, defined in `chat_turn/turn_stats.py` beside the first-token clock (`_FirstVisibleClock`, `_turn_clock`) whose reading `_turn_persist_and_settle` (`chat_turn/stop_recovery.py`) passes as `ttft_ms`, and bound on `chat_runner` (the binding tests import), writes `meta["turn_stats"]` on the turn's reply row and returns whether a row received it. The row is `_completed_reply_row`: among the rows appended since the turn began (`_turn_rows`, scoped by `turn_boundary` and the start identity `turn_start_mid` the runner also hands `_flush_file_changes_off_loop`), the newest reply the runner recorded (`_last_reply_row`, so a workflow or sub-agent envelope another writer appended after the reply does not take the turn's figures), or, for a turn that recorded no reply (a slash command's confirmation is appended as a plain assistant row), the newest assistant row that is not a system notice. `TestAttachTurnStats.test_error_only_turn_does_not_overwrite_previous_turn` and `test_boundary_scopes_to_current_turn_assistant` enforce the boundary: without it, an error-only turn could overwrite the prior turn's measurement; `test_lands_on_the_recorded_reply_not_a_row_another_writer_appended`, `test_a_turn_that_recorded_no_reply_keeps_the_position_rule` and `test_passes_over_a_system_notice_after_the_reply` pin the row rule, and `TestAbnormalEndFooter.test_a_completed_turn_leaves_a_row_another_writer_appended_alone` drives it through the real `_run_chat`. The helper does not fabricate a message, and it returns without a positive elapsed measurement. The post-turn persistence block skips the helper for `_retrying_empty` turns.

The helper preserves pre-existing `meta`, always records a positive `elapsed_ms`, records `ttft_ms` only when positive (chat turns pass it; the footer does not render it), records `retries` only when positive (how many times a top-level chat turn re-sent the user turn after a pre-output transient error, from `slot._turn_retries`; the footer does not render it either), and omits non-positive credits, cost, and empty model values. It also drops a non-finite credit or cost (`json.dumps` writes `inf`/`nan` as a bare `Infinity`/`NaN` that no browser parses), scrubs the model id with `_redact_acp_string` (credentials and suspicious URLs), and drops a model longer than `_MAX_MODEL_ID_LEN` — all of which applies to chat turns too, since `turn_stats_meta` is the one builder both writers share. `TestAttachTurnStats.test_credits_rounded` pins credit precision; `test_preserves_existing_meta`, `test_zero_credits_key_omitted`, `test_zero_cost_key_omitted`, and `test_model_omitted_when_unattributable` pin the remaining contract.

### Turns that end abnormally

A turn that ends without running the end-of-turn attach goes through `_persist_partial_reply`, which saves the partial reply, puts the footer on (`_stamp_abnormal_turn_footer`), and writes the usage row (`_record_abnormal_turn_usage`). That covers a Stop press (`_run_chat`'s `CancelledError` arm), an involuntary cancel (`error: cancelled`: tab close, idle sweep, shutdown, turn ceiling), a terminal provider error, a transient one such as the model at capacity after the reply started streaming (the post-token seam, `error: transient attempt`), the generic `Exception` arm (`error: terminal`: a prompt or session-start timeout from the shared runtime, an internal error), and the four arms that complete the turn and then return before the end-of-turn flush to queue a recovery (`stale_recover`, `error: tool stall`, `error: compaction failed`, and a retryable `error:` failure). Those four arms and the generic arm never reach the end-of-turn flush, so the seam is what saves their streamed text as a reply rather than leaving it as chunk rows, which a save drops. `_stamp_abnormal_turn_footer` calls `_attach_abnormal_turn_stats`, which writes `turn_stats_meta` (the completed-turn shape) from the wall-clock elapsed time, the recovered credits and cost, and `read_turn_model` onto `_last_reply_row` (in `chat_turn/turn_stats.py`), so the reply the turn left shows the completed-turn footer whatever ended it. `_last_reply_row` is the one identity walk, which `_attach_file_changes` also calls to place the turn's file chips: among this turn's rows (`_turn_rows`), the newest reply the runner recorded (`slot._turn_reply_mids`), because a workflow or sub-agent envelope another writer appends mid-turn is not the turn's reply. It also passes over a system notice (`is_system_notice`), which is written under the assistant role but is not a reply: a failed compaction appends its notice after the text the user read. The stats also go out at once on a `chat_message_update` patch (`_broadcast_turn_stats`, keyed on the row's `mid`), because an abnormal end can hand the slot straight to a queued recovery, which sends no `chat_done`, and so no refresh, until it finishes; the usage row keeps the arm's own `stop_reason`. A recovery the runner queues after the error is a separate turn with its own stats, so a resumed answer ends with a footer of its own below the error card. The attach is gated on `_turn_boundary_set`, which dispatch sets when it captures `_turn_msg_boundary`: a turn that ends before dispatch (during pre-prompt preparation) still reads boundary 0, would overwrite the previous reply's footer, and so writes only the usage row. The footer and the row share ONE `provider_last_turn_usage` read, passed to `_persist_abnormal_turn_usage(usage=...)`: the read consumes the accumulated multi-attempt total, so a second read would give the row only the last attempt. A turn that ended before it appended any reply row gets no footer, since there is no row to carry it; a pre-stream transient retry re-runs the same turn and appends none.

When `EVENT_COMPLETE` already billed the turn (`_turn_usage_persisted`) and the turn was cut before the completion's own attach, the seam does not read or bill again: it attaches the figures the completion captured (`_turn_stats_captured`: `_turn_elapsed_ms`, `_turn_credits`, `_turn_cost_usd`, `_turn_model`, and the first-token clock's `ttft_ms`, so the footer is the one the completion would have written), once (`_turn_footer_attached`). That is the turn ceiling's usual end: `_bounded_turn` sends the native agent a stop before it cancels the task, an agent that acknowledges ends the prompt as `cancelled`, and the task cancel then lands on an await between the completion's usage write and its attach. It is also the four recovery arms' end when their completion billed; a completion that reported no billing wrote no row, so the seam handles that turn like one that never completed: one read, the footer from it, and a row under the arm's own `stop_reason` if the provider still holds credits for the turn. `_persist_partial_reply` appends the text once per turn (`_reply_flushed`, which the end-of-turn flush sets too, since the flushed text stays in `assistant_text` for the legs after it), so a cancel or an error landing after the flush does not save the reply a second time; and a cancellation of its shutdown save is swallowed, as `_persist_abnormal_turn_usage` swallows one on the usage write in the same teardown, so it never costs the calling arm its card, its recovery or the usage row. The in-place meta write marks the slot dirty itself (`slot._dirty`), as every in-place row edit must: the periodic flush writes only a dirty slot, and one that ran after the reply was saved would otherwise leave the footer off disk; while the gateway shuts down the teardown skips its save, so the footer goes on before `_persist_partial_reply`'s own shutdown save, which also runs when the footer is the only new thing on the reply. `TestStoppedTurnFooter` and `TestAbnormalEndFooter` in `test/test_chat_runner_abnormal_turn_usage.py` pin the footer on each end (a Stop, an involuntary cancel, a terminal error, a post-token transient, a stall recovery, a prompt timeout, a cancel after the completion), the shared read, the elapsed-only footer of an unbilled stop, that an end before dispatch leaves the previous footer alone, and the one saved row. `TestErrorEndTurnFooter` pins the seam around that stamp: the turn ceiling through the real `bounded_chat_turn` (native stop acknowledged or not, the acknowledged one keeping the completion's figures, `ttft_ms` included), the footer in the shutdown save, the single save of a reply an end reaches after the flush, a recovery arm billing a turn its completion did not, a cancellation of the shutdown save that still leaves the arm its card, recovery and row, the live patch a stall sends before its queued recovery runs, after the reply's own row frame, the footer of a failed compaction landing on the reply rather than its notice, a late end after a completed turn's footer neither stamping nor patching it again, the dirty mark a footer leaves after a periodic flush, and the footer in a window at its cap; the module-level `_last_reply_row` tests pin the notice skip and the identity rule.

### Cron run results

`chat_turn.turn_stats.turn_stats_meta` builds the same `turn_stats` dict for both writers. The single-agent cron run in `slack/gateway_runtime/cron_turn.py` builds it from the run's `provider_last_turn_usage` and `read_reported_turn_model`, and `cron_inject.inject_cron_result_to_dashboard` passes it as `meta` on the result row's `slot.append`, so the live broadcast and the slot window both carry it. It also passes it (as `row_meta`) to the durable `cron:{id}` append, so a restart before the slot save keeps the footer. Cron results have no `chat_done`; the broadcast is what an open tab renders. `test/test_cron_turn_stats_footer.py` pins all three — the broadcast row, the durable `cron:{id}` row (`test_durable_cron_row_carries_turn_stats`), and that an inject with no stats stamps nothing.

### Model attribution

`dashboard.handlers.usage.read_turn_model` returns a concrete resolved model identifier when one is available, the `auto` sentinel for an Auto request without a resolved identifier, or an empty string when neither is known. A session on the default model counts as an Auto request: its start path never calls `set_model`, so `_model` stays empty, while `session/new` stores the backend's `currentModelId` of `auto` as `_resolved_model_id`, and that backend-reported `auto` yields the sentinel. An empty `_model` with an empty or missing `_resolved_model_id` stays empty. `TestReadTurnModel` enforces the precedence and the unattributable case, and `TestBackendReportedAutoIsAttributed` (`test/test_usage_model_attribution.py`) pins the default-model session shape on the real provider classes. The sentinel distinguishes an explicit Auto selection from absent attribution; callers that need a concrete identifier for pricing or context-window lookup use `read_effective_model` instead.

`read_reported_turn_model` is what both footers show: the model the harness reported serving the turn (`turn_model`, from the prompt response's `model_usage`), else `read_turn_model`. The harness spells a model its own way (`global.anthropic.claude-opus-5-5[1m]` for `claude-opus-5.5`), so the usage record keeps `read_turn_model` and one model's usage history does not split in two.

## Frontend

`website/src/pages/chat/page/transcriptRendering.tsx` (ChatPage's bubble renderer, `bubbleRenderer`) passes `m.meta.turn_stats` to `AssistantMessage` only when `ChatConfig.showTurnStats` is true. `ChatSettings.loadChatConfig` defaults and repairs that persisted setting as enabled under `mc-chat-config`; `ChatPanel` does not currently expose a control for it. `website/src/app-sdk/messageRenderers.tsx` separately forwards `turn_stats` without consulting `ChatConfig`.

`website/src/pages/chat/AssistantMessage.tsx` renders the footer only when the message is not streaming, `showFooter` is true, and `turnStats.elapsed_ms` is positive. `showFooter` (the stats line AND the action row: Copy, Fork, More) comes from one rule, `replyShowsFooter` in `website/src/pages/chat/replyFooter.ts`, which the page's transcript renderer (`website/src/pages/chat/page/transcriptRendering.tsx`) and the SDK's `renderAssistantBubble` both call with the row they draw and the list the walk reads after it: the page draws a deferred snapshot of its rows and hands the walk the live list, so the row's own role and stats come from the row passed in, never from the list at its index. A reply carrying positive persisted `turn_stats` always draws it: the runner stamps them on every turn end, so whatever is drawn below that row -- an auto-nudge cycle, an error card and the recovery after it, a cron run, a run another tab started -- belongs to a later turn and must not retract the footer. A reply without stats draws it once its turn is over: a user row follows (a steer too), or a row that opens a turn of its own (`opensTurn`: a nudge, a sub-agent completion, a cron, synthesis or app inject), or the transcript ends and the slot is no longer running; another reply first means the turn goes on, and a hidden say-nothing row or a system notice is passed over. A crewmate's chat additionally forces the footer onto a run's last bubble (`forceFooter`). Together with the backend boundary, these gates prevent an in-progress or earlier assistant segment from presenting the completed-turn footer without retracting an already completed turn's metadata. `groupDisplayItems` reads the same stamp as the end of a fan-out synthesis answer; an error card or a system notice after a stamped reply, before any other reply, ends that answer too, since it reports on the turn that wrote it, and another writer's envelope in between (a workflow result or a sub-agent completion, which the runner never records as its reply) is passed over; where a `recovery` inject follows, the turn was resumed and the answer runs on to the next stamped reply. The stamp is therefore a contract between the runner and the page, not only a carrier of figures: the page reads `turn_stats` on a reply as the end of its turn (`isTurnEnd`, `answerEndIndex`, `findResumedReplyRows`), so a writer that stamps a row other than the turn's last reply moves the answer's end and the fold to that row. `test/test_turn_stats.py` (`test_turn_stats_lands_only_on_the_row_the_two_selectors_chose`) holds that on the backend: a scan of `src/kiro_crew` finds every write of `meta["turn_stats"]` and requires its row to come from `_completed_reply_row` or `_last_reply_row`; the only other places the key is built are the live patch's frame (`_broadcast_turn_stats`) and the cron result row, which `inject_cron_result_to_dashboard` appends with its own run's figures, and a new one fails that test by name until it is traced. The runner's own status lines (an unattended approval timeout, an agent switch) carry no marker, so one drawn after the stamped answer still reads as the next reply. `TurnBlock` (`website/src/pages/chat/TurnBlock.tsx`) keeps that reply out of the collapse-all fold as well: a stamped reply that a `recovery` inject resumed, and the recovery row itself, stay visible above the recovered remainder (`findResumedReplyRows`, on the grouper's row predicates), so the first half of a cut-short answer is read rather than folded as a step; only an error card, a system notice or another writer's envelope may sit between the two, stamped text a tool call followed is narration and folds, and a cut reply without the stamp folds as before. The synthesis row directly above the cut reply is pinned with it: the grouper opens the answer's turn on that row, so with the halves pinned it would be the one step left for a toggle to hide, where `main` shows it as a loose row; a synthesis row a tool call separates from the reply folds with that step. The MCP App promotion pass in `website/src/pages/chat/page/transcriptRows.ts` also ends a loose region at a stamped reply; a cut-short reply is safe there because any row after it makes an app-bearing batch long enough that the grouper has already made it a turn, which the pass keeps whole (`groupDisplayItems.test.ts` pins the grouper half, `transcriptRows.cutReply.test.tsx` the pass itself over the real `useTranscriptRows`).

The footer is visible rather than hover-revealed, uses muted tabular numerals, and places a clock beside elapsed time. Only the optional model label uses the monospace face; `messageFooterFont.test.tsx` protects the footer-level font-setting contract. It displays credits when positive and otherwise displays positive dollar cost; elapsed time always follows the billed value. `fmtTurnModel` trims known routing prefixes for the inline label while the title retains the untrimmed model identifier. `fmtTurnElapsed` (`AssistantMessage.tsx`) and `fmtCredits` (`website/src/i18n/format.ts`) format the values, and their formatter tests in `AssistantMessage.test.tsx` pin the display rules. Missing `turn_stats`, `showFooter=false`, and streaming messages render no stats footer.

## Tests

- `test/test_turn_stats.py` (`TestAttachTurnStats`) covers attachment, omission, rounding, current-turn targeting, model attribution, and meta coexistence; `test_turn_stats_lands_only_on_the_row_the_two_selectors_chose` scans the backend for every write of `meta["turn_stats"]` and requires its row to come from `_completed_reply_row` or `_last_reply_row`.
- `test/test_chat_runner_abnormal_turn_usage.py` (`TestStoppedTurnFooter`, `TestAbnormalEndFooter`, `TestErrorEndTurnFooter`) covers the footer on a reply a Stop, a cancel, the turn ceiling, a stall recovery or an error cut short, and the seam's ordering around it.
- `test/test_usage.py` (`TestReadTurnModel`) covers resolved, Auto, and unattributable model states.
- `website/src/test/AssistantMessage.test.tsx` (`turn stats footer`) covers rendering, ordering, model display, suppression gates, and formatters.
- `website/src/test/replyFooter.test.ts` covers the shared footer rule: stamped replies, turn openers, continuations, notices, streaming rows, and the drawn row's own stats where the live list holds another row at its index; `website/src/test/AppSdkMessageRenderersCov80.test.tsx` runs the stamped-reply and auto-nudge cases through the SDK renderer.
- `website/src/test/TurnBlock.test.tsx` (`a reply cut short and resumed`) covers the collapse-all pin: the cut reply and its recovery row stay visible above the resumed half, a notice or an envelope between them is passed over, stamped text a tool call followed still folds, a cut reply without the stamp folds, the synthesis row that led the cut reply stays with it and leaves nothing to fold, and a synthesis row a tool call separates from the reply still folds.
- `website/src/test/ChatPage.footerNotRetracted.test.ts` protects a completed footer from being retracted by a later run, and pins that `ChatPage` draws from the shared rule.
- `website/src/test/ChatSettings.test.tsx` covers the persisted `showTurnStats` default and validation.
- `website/src/test/messageFooterFont.test.tsx` verifies that the footer follows the configured font family.
