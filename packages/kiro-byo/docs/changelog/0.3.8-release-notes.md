# Kiro BYO 0.3.8 开发与升级说明

## 本次升级目标

修复 KiroCrew 0.12.0 在全局 ACP Harness 于官方 Kiro/KAS 与 Kiro BYO 之间切换后，队友（Mate）默认 Harness 不一致的问题。保留 BYO 独立 ACP Harness 的定位；**不将本轮表述为 Crew 官方无补丁第三方注册已经完成**。

## 实际源码修改

1. `src/kiro_byo/crew_shared_patch.py`：仅识别并删除 0.3.7 所安装的完整、BYO 自有的队友强制早返回保护分支，保留 Crew `select_provider_backend` 本来的优先级（会话覆盖 > 独立队友绑定 > 队友默认 > 主默认）；不允许修改不完整或外来补丁。
2. `src/kiro_byo/crew_current_patch.py`：使 `agent.member_acp_backend` 的**运行时有效默认**根据 `agent.acp_backend` 双向解析。BYO 主选项得到 `kiro-byo`；Kiro/KAS 官方主选项得到 Crew 的官方队友后端 `kas`。不覆写已保存用户设置。
3. `src/kiro_byo/crew_patch_common.py`：Dashboard 模型归属辅助函数与新队友默认规则对齐；严格识别 0.3.7 的旧辅助函数以支持升级。
4. 修正旧测试中错误地期望 BYO 覆盖所有队友显式选择的断言；补全升级安全、双向切换和未授权后端拒绝回归。

## 使用语义

- 全局 ACP 切到 BYO：**未单独绑定 Harness 的新队友会话**使用 `kiro-byo`；新 Worker 由 Crew 自身确定所属队友并选择有效后端。
- 全局 ACP 切回官方 Kiro/KAS：新队友会话走官方 `kas`，旧的全局成员 BYO 默认不再残留。
- 单个队友显式 `agents.<name>.acp_backend` 绑定与明确会话级覆盖保持其原生优先级；不强制所有有意固定的队友改用全局设置。
- **切换不热迁移正在执行的旧会话**：Crew 0.12.0 对一般 Harness 配置热变更只更新未来新建的 Provider Factory；已有会话进程及历史不自动转移。要确保某个已打开的队友使用新的 Harness，安全结束旧任务并创建/重建会话（必要时重启 Gateway）。旧 Harness 的模型 ID、强度或权限状态不得直接复制为新 Harness 的已认证能力。
- KiroCrew Gateway、模型 Provider、MCP/Worker 权限以及 Windows 桌面端实际对话尚未完整端到端验收；截图中的“工作中”是否由本问题导致，仍缺运行日志证实。

## 安装注意

建议在升级前保存 BYO 配置和 Crew 数据备份，在 Crew 没有执行任务时安装 0.3.8，并**重启 Gateway**让新的宿主源码和运行时生效。不要直接改写 Crew 上其他未经确认的补丁；安装器的语义预检和回滚机制会拒绝不兼容的结构。切换全局 Harness 后，使用新队友会话检验，不要拿正在使用旧 ACP 进程的会话作即时切换结论。
