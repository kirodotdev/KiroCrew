The ssh self-target floor keeps the DNS self-check on by default and turns it off only for a wildcard that _file_operand_indices proves is a plain operand of git add, and only when the whole submitted line is one simple git add command (is_one_plain_git_add_line: no ; | & ( ) { } $ < >, backtick or newline anywhere, only GIT_DIR=, GIT_WORK_TREE= or GIT_INDEX_FILE= assignments before the program word, and the program word bare git or one of /usr/bin/git, /bin/git, /usr/local/bin/git, /opt/homebrew/bin/git). So no function, alias or substitution written earlier on the line can change what git runs, and a line the floor reaches by recursion never gets the exemption. Inside that line the subcommand must be the lowercase word right after git, read in the original case, and the operand scan stops at a separator or a substitution edge. Programs whose every argument is a path (cp, ls, cat …) are already read by the data-consumer exemption, and tar is left out on purpose because tar -I / --rsh-command runs its argument. The lines are the one-line gate, the git-only detector with its plain-program check and one-entry subcommand table, and the walk's file-operand flag with its two operand-check wirings.
