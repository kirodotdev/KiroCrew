The shared shell quote walk (_iter_shell_chars) reads here-documents as bash
does: a << outside quotes opens a body on the next line, and the walk starts
unquoted where the body's closing line ends, so every reader built on the walk
(the $(...) and backtick close-finders among them) inherits it. A new module,
shell_heredoc_lines, decides once which << opens a body (heredoc_docs): it
tracks the same quotes, comments, ${...} / $[...] expansions and arithmetic
((...)) / $((...)) spans that read_commands tracked, so read_commands' own
opener code is deleted and it takes its bodies from the shared reader. The walk
reads the same decision lazily (heredoc_stream), so a line cut into many walks
stays linear. A $'...' tag is decoded with the shared ANSI-C decoder, and the
tag and closing lines are read in the case the command was submitted in
(is_denied keeps it in the call memo). Bodies of a folded text are found on the
text before folding (carry_docs), so a fold inside a quoted-tag body cannot make
a closing line. _self_tokens tokenizes in pieces cut around each body
(_heredoc_line_pieces), and the ssh floor's separator mask starts fresh after a
body's closing line (heredoc_body_spans).
cased_view gives no case when the submitted command holds the text in two cases,
a folded text's bodies are read lazily with offsets moved by bisect, and every
importer loads shell_heredoc_lines at its first << so the MCP listing's import
graph does not grow.
