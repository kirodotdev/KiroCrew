Issue #37684: `security/mcp_body_fields.py`'s `body_field_match_refusal` (was `warn_body_field_matches`) now refuses a message-body field over the 20 KiB command-scan ceiling that holds a hard credential: a credential-check match whose rule id is a GitHub, npm or DigitalOcean token, a labelled AWS secret that passes the label rule's own gate or has the bare key's shape, or a private-key block with a base64 body line after a header (`_HARD_CREDENTIAL_RULES`, read from the redaction's own match records), in the text or in a percent-decoded form of one of its links (`_link_decodings`); any other match is judged again word by word by the whole credential check (`_record_is_hard`). Every other hit, and any hit in a shorter field, is still only logged. The lines are the refusal branch, its reason text, the hard-kind set, the link decoding, the wrapped-token reclassification, and the docstrings that say which size and which kind get which answer.
Over 20 KiB a token or key line counts only when it looks random (`_looks_random`) and a token only where it starts a word (`_starts_a_word`), so placeholders and token shapes inside random tracking data are sent as on main; a link is also read form-decoded (`unquote_plus`).
A key's armour header lines (`Proc-Type:`, `DEK-Info:` and OpenPGP's `Version:`, `Comment:`, `Hash:`, `Charset:`, `MessageID:`) are skipped before its base64 lines are judged (`_ARMOUR_HEADERS`).
A token body with no digit still counts when it is letters only with eight or more different ones and spells no placeholder word (`_is_token_body`), so a real npm or GitHub token whose body has no digit is refused.
In a percent-decoded form of a link an AWS secret match the key-ID pairing row read (`_PAIRED_AWS_ROW`, a 40-character run of a presigned link's percent-split session token) is not hard and is sent, as on main; in the body text every AWS secret match is judged as before.
