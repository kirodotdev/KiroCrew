Issue #37684: `security/mcp_body_fields.py`'s `body_field_match_refusal` (was `warn_body_field_matches`) now refuses a message-body field over the 20 KiB command-scan ceiling that holds a hard credential: a credential-check match whose rule id is a GitHub, npm or DigitalOcean token, a labelled AWS secret of the bare key's shape, or a private-key block with a base64 body line after a header (`_HARD_CREDENTIAL_RULES`, read from the redaction's own match records), in the text or in a percent-decoded form of one of its links (`_link_decodings`); any other match is judged again word by word by the whole credential check (`_record_is_hard`). Every other hit, and any hit in a shorter field, is still only logged. The lines are the refusal branch, its reason text, the hard-kind set, the link decoding, the wrapped-token reclassification, and the docstrings that say which size and which kind get which answer.
Over 20 KiB a token or key line counts only when it looks random (`_looks_random`) and a token only where it starts a word (`_starts_a_word`), so placeholders and token shapes inside random tracking data are sent as on main; a link is also read form-decoded (`unquote_plus`).
